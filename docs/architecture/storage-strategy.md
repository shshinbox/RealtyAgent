# 데이터 저장소 설계 전략

## 개요

본 문서는 RealtyAgent의 정보 저장 및 검색 전략을 정의합니다.
시스템이 다루는 정보는 출처에 따라 두 가지로 분류되며, 각각 독립적인 저장 전략을 적용합니다.

---

## 정보 출처 분류

| 분류 | 설명 |
|---|---|
| **사용자 발화 정보** | 대화 중 사용자가 직접 언급한 내용. 동적이며 개인적인 비정형 데이터 |
| **공문서 정보** | PDF, 웹사이트 등 공식 출처 기반의 외부 문서 데이터 |

---

## A. 사용자 발화 정보

### 저장 구조 (기본)

| 저장소 | 저장 내용 | 목적 |
|---|---|---|
| PostgreSQL (대화 이력) | 원본 대화 전체 (시간순) | 세션 재개, 단기 컨텍스트 로딩 |
| PostgreSQL JSON (사용자 프로필) | GLiNER 추출 엔티티 누적 | 장기 조건 보정 (지역 / 예산 / 평형 등) |

### 설계 판단

- 순서 보장이 핵심이므로 관계형 DB(PostgreSQL)를 사용합니다.
- 사용자가 대화 중 언급한 조건은 GLiNER를 통해 엔티티로 추출하여 프로필에 누적 갱신합니다.

---

### [Optional] Vector DB - 사용자 발화 장기 의미 검색

> 본 항목은 현재 설계 범위에서는 제외된 선택적 확장입니다.
> 구조화된 엔티티(GLiNER) 추출로 대부분의 맥락 보정이 가능하나,
> 아래 조건이 필요해지는 시점에 도입을 검토합니다.

**도입 조건:**
사용자가 조건이 아닌 **의견, 감정, 서술형 맥락**을 언급했고, 이를 나중에 의미적으로 검색해야 하는 경우.

**예시:**
```
과거 발화: "학군보다는 조용한 주거 환경이 더 중요한 것 같아요"
→ GLiNER로는 구조화 추출 불가
→ "조용한 환경 선호" 관련 발화를 나중에 유사도 검색으로 꺼내야 함
```

**저장 방식:**
- 저장 단위: Q+A 세트를 하나의 텍스트로 병합하여 임베딩
- 컬렉션: `conversations` (공문서 컬렉션과 반드시 분리)
- 메타데이터: `user_id`, `session_id`, `timestamp`

**검색 방식:**
- 트리거: 현재 질문이 구조화 조건으로 해소되지 않을 때
- 방법: 현재 발화를 쿼리 벡터로 변환 → 유사도 상위 3~5개 과거 교환 반환
- 활용: 반환된 과거 교환을 프롬프트 컨텍스트로 주입

**PostgreSQL과의 차이:**
| | PostgreSQL 이력 | Vector DB 발화 |
|---|---|---|
| 검색 기준 | 시간 순서 | 의미적 유사도 |
| 범위 | 최근 N턴 | 전체 세션 장기 |
| 용도 | 단기 맥락 | 의미 기반 장기 맥락 |

---

## B. 공문서 정보

### 저장 구조

| 저장소 | 저장 내용 | 목적 |
|---|---|---|
| Vector DB `[collection: documents]` | 청킹된 문서 임베딩 | RAG 기반 유사도 검색 |
| Graph DB | 문서 내 개체 간 관계망 | 다단계 추론 (GraphRAG, 후순위) |

### 설계 판단

- PDF, 웹 문서 등 공문서는 청킹 후 임베딩하여 Vector DB에 저장합니다.
- Vector DB 컬렉션은 사용자 발화 정보와 **반드시 분리**하여 운영합니다.
- Graph DB 기반 GraphRAG는 문서 내 개체 간 관계 추론이 필요한 시점에 도입합니다.

---

## 맥락 보정 실행 흐름

사용자가 조건을 생략하거나 불완전한 질문을 한 경우, 아래 순서로 정보를 수집하여 프롬프트를 구성합니다.

```
사용자 질문 입력
  ↓
① PostgreSQL 대화 이력     → 최근 N턴 로딩 (단기 맥락)
② PostgreSQL 사용자 프로필 → GLiNER 누적 엔티티 조회 (장기 조건)
③ Vector DB [documents]    → 관련 공문서 청크 검색 (도메인 지식)
④ [Optional] Vector DB [conversations] → 의미 기반 과거 발화 검색 (서술형 맥락)
  ↓
수집된 정보를 합산하여 프롬프트 구성 → LLM 응답 생성
```

---

## 요약

```
사용자 발화
  ├── PostgreSQL (대화 이력): 원본 보존, 단기 로딩
  ├── PostgreSQL JSON (프로필): GLiNER 엔티티 누적, 장기 조건 보정
  └── [Optional] Vector DB [conversations]: 서술형 발화 장기 의미 검색

공문서
  ├── Vector DB [documents]: RAG 유사도 검색
  └── Graph DB: 관계 추론 (GraphRAG, 후순위)
```
